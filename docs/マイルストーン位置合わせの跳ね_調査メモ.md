# マイルストーン位置合わせで工数が跳ねる件 ― 原因と対処

実データ(完了案件 30 件 / マイルストーン記入 22 行 / 主なマイルストーン 3 種)で
位置合わせを ON にしたところ、月次工数に大きすぎる跳ねが出た。
一番工数が大きく期間の長い案件のマイルストーンを消すと収まった、という報告に対する調査記録。

---

## 1. 結論

跳ねはバグではなく、**区分線形ワープの構造上そうなる**。

工数密度は質量保存から

    実時間軸の密度 = 正準時間軸のカーブ ÷ 伸縮率(du/ds)

で決まる。ワープは区分線形なので **伸縮率は区間ごとに一定で、アンカー(マイルストーン)の
前後で不連続に切り替わる**。隣り合う区間の伸縮率が k 倍違えば、そのアンカーの位置で
月次工数がそのまま k 倍跳ぶ。これが「跳ね」の正体である。

報告された案件が特に跳ねたのは、次の3つが重なったため。

| 条件 | 効き方 |
|---|---|
| マイルストーン1までが長い(実位置 0.55 に対し正準位置 0.28) | 前半区間が 1.9 倍に引き伸ばされ、その次の区間が 0.5 倍に圧縮される。両側の比 = **約 4 倍** |
| 期間が長い(36ヶ月) | 圧縮された区間にも月が 6 個ほど入るので、跳ねが月次グラフにそのまま出る。短い案件なら月内でならされて見えない |
| 工数が最大(3000人月) | 同じ倍率でも絶対値が大きく、グラフ上で突出する |

**マイルストーンを消すと収まったのは、その案件のワープが恒等写像に戻り、
伸縮率の不連続が消えたから。**跳ねの原因を取り除いたのではなく、位置合わせごと
無効にしただけなので、位置合わせの効果も同時に失われている。

## 2. 再現

`scripts/repro_alignment_spike.py` で最小再現できる。
報告と同じ構成(30案件 / マイルストーン 3 種 / 記入は一部の案件のみ)の合成データを作り、
異質な大型長期案件を leave-one-out で予測する。

```
現状(マイルストーンあり)
  ワープ: α版 0.283->0.549 / β版 0.636->0.719 / マスターアップ 0.906->0.930
          [最大密度倍率 2.07 / アンカー段差 4.03]
  予測 ... 42.2  47.3  81.3 156.1 103.7 ...     ← α版アンカーの位置で 3〜4 倍に跳ぶ
  実績 ... 205.3 218.1 177.2 115.7  80.7 ...
  跳ね度 1.49 / WAPE 0.490
```

跳ねの倍率 (47.3→81.3→156.1、約 3.3 倍) が、ワープのアンカー段差 4.03 とほぼ一致する。
これが「密度 = カーブ ÷ 伸縮率」の直接の帰結であることの確認になる。

## 3. なぜアンカーがそこまで極端になるのか

正準位置(= 揃える先の位置)は **そのマイルストーンを記入している案件だけの平均**である
(`learning.canonical_anchor`)。今回のデータは 30 案件に対し記入 22 行 / 3 種なので、
1 種あたりの母数は 10 件に満たない。

- 母数が少ないほど平均位置そのものが不安定
- しかも問題の案件自身がその平均に入っている(自分で引っ張った平均に自分を合わせる)
- 記入の無い案件は恒等写像のまま平均に混ざるので、正準カーブは「揃った案件」と
  「揃っていない案件」の混合になる

`scripts/diagnose_warp.py` は各背骨マイルストーンの平均位置・標準偏差・記入件数を
先頭に出す。**標準偏差が 0.1 を超える、または記入件数が案件数の半分を切る**
マイルストーンは、背骨として使うと極端な伸縮を生みやすい。

なお `背骨マイルストーン` を明示指定した場合、`背骨最小カバー率` は無視され
**2 案件で採用される**(`choose_backbone`)。指定運用をしているなら、母数は必ず確認すること。

## 4. もう一段ひどくなるケース(実データで起きうる)

`Warp.build` は単調性を保つため、実位置を `min_gap = 0.02` 以上あけるようクリップする。
日付が近接・逆順だと、正準側で広い区間が実時間軸の 2% に押し込まれる。

| マイルストーン日付 | 最大密度倍率 | アンカー段差 |
|---|---|---|
| 正常 | 1.1 倍 | 1.3 倍 |
| β版とマスターアップが同月 | **15.0 倍** | **28.2 倍** |
| 日付が逆順(β版がα版より前) | **16.5 倍** | **38.5 倍** |
| 3つとも終盤に集中 | **16.5 倍** | **48.4 倍** |

手入力のデータでは十分に起こりうる。従来はこの補正が黙って行われていたため、
利用者には原因不明の巨大な跳ねだけが見えていた。
今回、補正が起きた案件を警告に出すようにした(下記)。

## 5. 入れた対処

### 5-1. 見えるようにした

- `Warp` に `stretch_factors()` / `max_density_gain` / `max_step_ratio` / `clipped` を追加。
  `warp.describe()` が最大密度倍率とアンカー段差を併記するようになった。
- 学習時、アンカー段差が 3 倍以上の案件と、日付補正が起きた案件を警告に出す
  (出力Excelの警告シートにも載る)。**どの案件が跳ねの原因かが名指しで分かる。**
- 予測時、対象案件のアンカー段差が 2 倍以上なら予測シートの注記に出す。

### 5-2. 抑えられるようにした

settings に 2 つのパラメータを追加した。既定値は従来の挙動と同じなので、
何もしなければ結果は変わらない。

| パラメータ | 既定 | 意味 |
|---|---|---|
| `位置合わせ強度` | 1.0 | 0〜1。実位置を正準位置へ向けて引き戻す割合。1.0 = 日付ちょうどに合わせる(従来)。0.0 = 位置合わせなし。**間の値が取れる**のがポイントで、「マイルストーンの情報は使うが、極端な位置には引きずられない」を表現できる |
| `伸縮率上限` | 0(無制限) | 区間ごとの伸縮率を 1/k〜k 倍に収める。跳ねの高さに直接上限をかける |

CLI からは `--warp-strength 0.7` / `--max-stretch 1.5`。

再現データでの効果:

| 設定 | 跳ね度 | WAPE |
|---|---|---|
| 現状(強度 1.0) | 1.49 | 0.490 |
| その案件のマイルストーンを削除 | 0.61 | 0.560 |
| **位置合わせ強度 0.5** | **0.82** | **0.452** |
| **伸縮率上限 1.5 倍** | **0.85** | **0.428** |

マイルストーンを削除すると跳ねは消えるが精度は最も悪い(0.560)。
強度を下げる・上限をかけるほうが、**跳ねを抑えつつ精度も改善する**。

### 5-3. 診断できるようにした

`scripts/diagnose_warp.py` を追加した。leave-one-out で全案件を回し、
案件ごとに アンカー段差 / 密度倍率 / 跳ね度 / WAPE を出し、設定値を並べて比較する。

```
python scripts/diagnose_warp.py
python scripts/diagnose_warp.py --strengths 1.0 0.7 0.5 --max-stretch 1.5
```

## 6. 実データでやること

1. `python scripts/diagnose_warp.py` を実行し、**段差比の大きい案件**を確認する。
   報告された案件が先頭に来るはず。来なければ別の原因なので、この調査結果は当てはまらない。
2. 先頭の案件について、**milestones シートの日付が実態と合っているか**を先に確認する。
   `補正MS` 列に名前が出ている案件は日付が近接・逆順で、まず入力の問題を疑う。
3. 日付が正しいなら、`--strengths` の比較表で **WAPE を悪化させずに跳ね度が下がる設定**を探す。
   見つかったら settings の `位置合わせ強度` / `伸縮率上限` に書き込む。
4. 見つからない場合(強度を下げると必ず WAPE が悪化する場合)は、
   位置合わせ自体は正しく効いているということなので、跳ねは受け入れるか、
   その案件を学習から外す(種別が違う案件として扱う)かの判断になる。

## 7. 残っている課題

- **ワープが区分線形である限り、伸縮率の不連続そのものは消えない。**
  根本対処はワープを単調3次補間(伸縮率が連続に変化する)に置き換えることだが、
  逆変換と質量移送の両方に手が入るため、今回は入れていない。
  `位置合わせ強度` / `伸縮率上限` は跳ねの高さを抑える対症療法である。
- 正準位置を「記入した案件の単純平均」で決めている点は変えていない。
  母数が少ないマイルストーンを背骨から外す、記入件数で重み付けする、といった
  改善余地がある。まずは `diagnose_warp.py` の先頭に出る標準偏差・記入件数を見て、
  背骨の選び方(`背骨最小カバー率`)で調整すること。
